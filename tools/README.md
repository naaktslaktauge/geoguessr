# 出題地点データの生成ツール

`js/locations.js` を作り直すためのスクリプトです。普段のプレイでは使いません。
地点を数件足すだけなら `js/locations.js` を直接編集するほうが早いです。

## ファイル
### 手作業リスト（名所・ランドマーク 344件）
| ファイル | 内容 |
|---|---|
| `part1〜4.py` | 地点の一覧（表示名・検索クエリ・国コード・エリア・難易度） |
| `geo3.py` | 検索クエリから座標を取得（Photon / Nominatim） |
| `snap.py` | 最寄りの車道上へ座標を吸着（Overpass API） |
| `cross.py` | 2つの地理サービスを突き合わせて誤りを検出 |
| `gen.py` | 344件版の `js/locations.js` を生成 |

### 一括生成（都市データ 約10万件）
| ファイル | 内容 |
|---|---|
| `countries.py` | 対象の国・地域とエリアごとの追加目標件数 |
| `pick_cities.py` | GeoNames の都市データから条件に合う地点を選ぶ |
| `snap_add.py` | 追加分を道路へ吸着（任意。Overpass が重いときは省略可） |
| `gen_all.py` | 手作業リストと追加分を統合して `js/locations.js` を生成（1,000件版） |
| `build_big.py` | 10万件版を一気に生成（コンパクト形式） |
| `difficulty.py` | 難易度の配点と、エリア内の相対順位への割り当て |
| `pick_tail.js` | 生成物の末尾に付ける抽選関数 |

### そのほか
| ファイル | 内容 |
|---|---|
| `stamp.py` | `index.html` の `?v=` をファイルの中身から打ち直す |
| `test_difficulty.py` | 難易度ロジックと `?v=` の検査（`test/run-tests.command` から呼ばれる） |

`stamp.py` は**コミットの前に必ず実行**します。以前は全ファイルに同じ番号を
振っていたため、`fx.js` を1行直しただけで `locations.js`（gzipで1.4MB）まで
再ダウンロードされていました。中身が変わったファイルだけ値が変わります。

一括生成には GeoNames のデータが必要です。2つ落とします。

```bash
# 世界の都市（人口500人以上・235,674件）
curl -O https://download.geonames.org/export/dump/cities500.zip
unzip cities500.zip -d tools/

# 日本だけの全居住地（50,801件）
curl -O https://download.geonames.org/export/dump/JP.zip
unzip JP.zip -d tools/

python3 tools/build_big.py tools js/locations.js
```

`JP.zip` を落とさなくても動きますが、日本は `cities500` に 2,190 件しか無いので
そこで頭打ちになります。日本単独のデータには人口が登録されていない
小さな町まで入っていて、その9割に漢字表記が付いています。
日本はストリートビューが全国に整備されているので、そこまで使えます。

件数は `build_big.py` 冒頭の `QUOTA` で決めます。
アフリカとオセアニアは GeoNames の収録自体が少なく、現在の値がほぼ上限です。

難易度は `difficulty.py` で決めています。「国の見分けやすさ」を主、
「街の知名度」を従として点数化し、**エリア内の相対順位**で3段階に割り当てます。
名所344件も同じ物差しで採点し、象徴性だけを上乗せ分として反映します。

以前は人口と首都かどうかだけで判定していましたが、
無名の大都市が「やさしい」になり、全体の81%が「むずかしい」に偏っていました。

10万件に増やしたときは別の壊れ方をしました。日本の小さな町は GeoNames が
人口も別名もほとんど持っておらず、**3万件以上が同じ点数**になります。
その塊の途中で「上位12%」の線を引くと、区別が付かないのに片方だけ「やさしい」に
なってしまいます（人口0の集落が東京と同じ扱いになっていました）。
`assign_by_rank` は**同点を必ず同じ難易度にし**、枠に収まりきらない塊は
丸ごと下の段へ送ります。

## 手順
```bash
python3 tools/geo3.py tools      # 座標を取得   → geo.json
python3 tools/snap.py  tools     # 道路へ吸着   → geo_snapped.json
python3 tools/cross.py tools     # 誤りの検出（25km以上ずれた地点を報告）
python3 tools/gen.py   tools js/locations.js
```

## なぜ道路に吸着させるのか
名所ちょうどの座標は建物の中や歩行者エリアに落ちることが多く、
ストリートビューが表示されなかったり、表示されても移動できなかったりします。
最寄りの車道上に寄せることで、確実に道の上から始まり歩き回れるようになります。

## なぜ2つのサービスで突き合わせるのか
地名検索は思わぬ別の場所を返すことがあります。実際にこの方法で、
「佐賀駅」が京都の嵯峨に、「福井駅」が岡山県津山市に化けているのを検出しました。
独立した2つのサービスの結果が 25km 以上離れていたら、どちらかが誤っています。

## 画面の撮影（レイアウト確認用）
`screenshot.py` はヘッドレスの Chrome でゲーム画面を撮影します。
スマホ幅のレイアウトを目で確かめるために使いました。

```bash
python3 tools/screenshot.py 出力先ディレクトリ 390 844
```

Chrome のヘッドレスは指定しても CSS の横幅が 500px 未満にならないため、
本物のスマホ幅を再現するにはゲームを iframe に入れて幅を固定する必要があります。
このスクリプトはその方法を使っています。
