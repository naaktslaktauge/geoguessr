# 自動テスト

ブラウザを使わずにゲームのロジックを検証します。
macOS 標準の JavaScript エンジン（`osascript -l JavaScript`）で動くため、追加インストールは不要です。

## 実行
`run-tests.command` をダブルクリック、または

```bash
bash test/run-tests.command
```

## 中身
- **stub.js** — DOM / Leaflet / PeerJS / タイマーの偽物。ブラウザ無しで本体コードを動かすための土台
- **driver.js** — 実際のテスト。ホストとゲストを同一プロセス内で動かし、
  `net.js` の通信経路を通して対戦を最後まで進行させる

## 検証している内容
| 節 | 内容 |
|---|---|
| A | 部屋の作成、2人の参加、ロビー同期 |
| B | 全員回答モード：出題配信・回答収集・採点・ラウンド進行・最終結果 |
| C | 出題者ありモード：出題者の交代、出題者の得点なし、ゲストからの出題 |
| D | 異常系：進行中の乱入拒否、二重回答の無視、切断処理 |
| E | ソロプレイの回帰確認 |
| F | 網羅パターン：2〜4人 × 全員回答/出題者あり × ラウンド数の総当たり10通り |
| G | 時間切れ、不正な座標、権限のないメッセージ、異常な名前 |
| H | 途中離脱からの再参加：席・得点・回答の引き継ぎ、出題者の復帰、無関係な新規参加の拒否 |
| I | 退出ボタンの表示条件、確認ダイアログの動作、地図サイズの変更と保存 |
| J | 制限時間の同期：残り時間の配信形式、カウントダウン表示、端末間の時計のズレ |
| K | 開始地点に戻るボタン：APIキー無しでの動作、向きの保持、表示条件 |
| L | 多数決スキップ：必要票数、投票の取り消し、出題者の単独やり直し、重複防止 |

特に重要な検証（★印で表示）：
- 回答中は**地名を配信しない**（答えの漏洩防止）
- 他人の回答内容はラウンド終了まで配信しない
- 出題者は得点が入らず、全員が同じ回数だけ出題者になる
- プレイヤーが抜けても進行が止まらない
- 制限時間切れで正しく締まり、未回答者は0点になる
- 壊れた座標（null・NaN・範囲外・文字列など）を送りつけても得点が壊れない
- 出題者以外の出題、出題者自身の回答といった不正な操作を受け付けない
- 各ラウンドの得点合計が最終得点と一致する
- 抜けた人が戻ると同じ席・同じ得点で復帰し、回答済みならその回答が保持される
- 復帰した出題者が「回答者」に変わって自作問題で得点してしまわない
- 退出ボタンがゲーム中の全画面（7画面）に出て、メニュー類では出ない
- 確認ダイアログのキャンセルで処理が走らず、OK では1回だけ走る
- 地図サイズが上下限を超えず、選んだ大きさが次回も復元される
- 残り時間を絶対時刻ではなく「あと何ミリ秒か」で配信している
  （絶対時刻だと端末ごとの時計のズレがそのまま表示差になるため）
- 開始地点に戻るボタンが、向きまで含めて毎回まったく同じ地点に戻る
- スキップが回答者の過半数で成立し、ラウンド数を消費しない
- 終了したラウンドがスキップで巻き戻らない
- 候補が10件しかない条件で10ラウンド遊んでも出題が重複しない

なお、要素の初期表示状態（`hidden`）は `index.html` から自動で読み取ってスタブに反映しています。
HTML とテストで初期状態がずれて、検証が素通りするのを防ぐためです。

## 再現性
乱数は `test/stub.js` の `__seed` で固定してあり、何度実行しても同じ結果になります。
別の出題パターンで試したいときはこの値を変えてください。

地点データ（`js/locations.js`）を編集したあとにも実行しておくと安心です。
